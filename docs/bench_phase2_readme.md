## Software rasterizer vs. Vulkan

The same scene (a lit floor plus a grid of spinning cubes, 12 triangles each) rendered by the Phase 1 CPU rasterizer and the Phase 2 Vulkan renderer at 800x600, from 1 to 10,000 cubes.

![Frame cost vs. scene size, software rasterizer vs. Vulkan](docs/phase2_cpu_vs_gpu.png)

| Cubes | Triangles | Software render (ms) | Vulkan GPU (ms) | Vulkan CPU submit (ms) | Speedup (GPU time) | Speedup (incl. CPU submit) |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 14 | 16.572 | 0.013 | 0.075 | 1,275x | 221x |
| 10 | 122 | 15.909 | 0.013 | 0.068 | 1,224x | 234x |
| 100 | 1,202 | 17.821 | 0.016 | 0.078 | 1,114x | 228x |
| 1,000 | 12,002 | 19.689 | 0.031 | 0.198 | 635x | 99x |
| 10,000 | 120,002 | 29.452 | 0.128 | 1.158 | 230x | 25x |

Raw numbers: [`bench_results.csv`](docs/bench_results.csv). Speedup = software render time / Vulkan time.

### What the numbers show

- **The software renderer is dominated by a fixed per-pixel cost.** The 1-cube row draws only 14 triangles yet takes 16.6 ms, so almost all of that time is clearing two 800x600 buffers and shading the floor. Frame time only starts to climb past 1,000 cubes (19.7 ms, then 29.5 ms at 120,000 triangles).
- **Vulkan's GPU time stays in the tens of microseconds** up to 12,000 triangles and reaches 0.128 ms at 120,000.
- **At high object counts Vulkan is limited by the CPU, not the GPU.** At 10,000 cubes, recording and submitting the draw calls costs 1.16 ms, about 9x the GPU time. That works out to roughly 108 ns of CPU per draw call. Instancing or indirect draws would collapse those 10,000 draws into one, which is the obvious next optimization.
- Because CPU submission exceeds GPU time in every row, the **"incl. CPU submit" column is the more conservative headline number** (25x to 234x).

### Method

- Same scene and camera for both renderers, generated by one shared function (`bench_scene.h`). 800x600, Release builds (`/O2`, validation layers off), vsync off.
- Each stage runs 1 s of warmup, then averages 3 s of frames.
- **Software:** time spent clearing and rasterizing a frame, excluding the OpenGL blit and swap (those added only about 0.2 ms).
- **Vulkan GPU:** timestamp queries written at the top and bottom of the whole frame's command buffer, read back after the frame's fence signals.
- **Vulkan CPU:** wall-clock time spent updating uniforms, recording commands and submitting.
- Wall-clock frame time is not used for Vulkan: it sat at exactly 144 FPS (6.944 ms) in every run, which is the display's refresh rate, not rendering speed.

### Caveats

- **The renderers do not shade identically.** Vulkan evaluates 3 point lights per pixel and a procedural floor checker; the software renderer uses one directional light and a sampled floor texture. This favors the software renderer slightly.
- Both draw all 12 triangles per cube (no back-face culling).
- The software renderer is single-threaded.
- The smallest Vulkan GPU times (13 microseconds) are close to the timer's resolution, and the GPU may not be at full clocks while idling between paced frames. Treat the low-count GPU-time speedups as order-of-magnitude, not exact.
- Each number is a single run; run-to-run variance was not measured.

### Reproduce

```powershell
cmake -G Ninja -S . -B build-release -DCMAKE_BUILD_TYPE=Release
cmake --build build-release
.\build-release\ToyEngine.exe --bench
.\build-release\ToyEngineVk.exe --bench
```
